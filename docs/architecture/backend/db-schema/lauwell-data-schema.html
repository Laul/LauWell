LauWell data schema

What the Neon Postgres database holds, and how it relates to the phone. One model, two homes: the full history in Postgres, the single source of truth, and a recent slice of the same tables in Room. Firestore is removed in M9. Nothing here is built.

Where the data lives

Screens read Room. Postgres is the single source of truth.

New readings come in through Health Connect, land in Room, and are uploaded to Postgres through a small sync API that checks the Firebase sign-in token. Entries are written to Room first and sent from an outbox. Older history, a new phone or a reset refill Room from Postgres. Charts never query the cloud directly. File contents live in Cloud Storage, which also holds the nightly backups.

Tables

Tables and how they connect

Metric definitions (units, aggregation, chart kind) stay in code, so the database stores only the metric's id as text. There is no metrics table. Every table points to users.id, never to the Firebase uid; auth_identity maps a sign-in to a user, so the sign-in provider can change later.
